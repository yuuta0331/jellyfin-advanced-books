## Highlights

- **Direct Komga metadata synchronization:** Advanced Books can now import metadata stored in Komga's database through the Komga REST API. This path does not depend on or read `ComicInfo.xml`.
- **Exact file identity:** Komga Books are matched to Jellyfin Books by normalized filesystem path, not by title. Configurable prefix mappings support Docker, NAS and host paths such as `/data/manga => G:/Manga`.
- **Manual and automatic workflows:** test the saved Komga connection, run **Sync now**, use Jellyfin's **Sync metadata from Komga** Scheduled Task, or optionally synchronize after a Jellyfin library scan.
- **Safe by default:** the feature is disabled by default, duplicate/ambiguous paths are skipped, and unsupported Komga concepts are not forced into unrelated Jellyfin metadata fields.

## Komga connection

Configure the integration under **Dashboard -> Plugins -> Advanced Books -> Direct Komga metadata sync**.

Use a **Komga administrator API key** when possible. Basic authentication with a Komga administrator account is also supported when no API key is configured.

Administrator access on Komga is required for path-based matching because Komga intentionally hides the full Book `url` from non-admin users. The Advanced Books connection test detects a restricted response and reports the requirement instead of silently producing an all-unmatched synchronization.

The Komga server URL must be an absolute HTTP or HTTPS URL. Credentials embedded in the URL are rejected.

## Path matching

Synchronization uses the Komga Book `url` as its identity source.

Advanced Books supports:

- `file:/data/books/Series/Book.cbz`;
- `file:///data/books/Series/Book.cbz`;
- Windows file URIs such as `file:///G:/Books/Book.cbz`;
- normal Windows drive paths;
- Unix absolute paths;
- UNC paths; and
- percent-encoded filenames.

When Komga and Jellyfin see the same media through different mount points, add one prefix mapping per line:

```text
/data/manga => G:/Manga
```

The longest matching source prefix wins and directory boundaries are enforced. Matching can be case-sensitive or case-insensitive according to the plugin setting.

There is deliberately **no fuzzy or title-based fallback**. If multiple active Komga Books map to the same path, or multiple Jellyfin Books share the same normalized path, that path is skipped rather than choosing an arbitrary item.

## Metadata mapping

For an exactly matched Book, Advanced Books synchronizes compatible Komga metadata into Jellyfin:

- Book title and summary;
- Series title;
- release date and production year;
- integral issue / volume number;
- Series genres;
- publisher;
- Book and Series tags;
- ISBN;
- authors and supported comic-creator roles; and
- stable `KomgaBook` and `KomgaSeries` provider IDs.

Komga author roles are mapped to the closest Jellyfin people kinds, including Author, Illustrator, Penciller, Inker, Colorist, Letterer, Cover Artist, Editor and Translator. Unknown Komga roles are retained as role text and represented as Creator.

Series grouping uses a stable Advanced Books presentation key derived from the Komga Series ID. Advanced Books does not overwrite Jellyfin's internal `SeriesId`.

## Deliberately unsupported fields

Some Komga fields do not currently have an equivalent Jellyfin Book property. Advanced Books therefore leaves them alone instead of storing misleading values elsewhere. This includes:

- content language;
- reading direction;
- Series status; and
- age rating.

In particular, Komga content language is not copied to Jellyfin's `PreferredMetadataLanguage`, because that Jellyfin field controls metadata-provider behavior rather than the language of the book.

## Synchronization behavior

Only changed Jellyfin items are written. Re-running synchronization with unchanged Komga metadata leaves the Book untouched.

Books and Series are retrieved through Komga's paginated current REST endpoints. Series are loaded in bounded pages instead of issuing one Series request per Book, and concurrent synchronization passes are serialized.

A matched Book is left unchanged if its active Komga Series metadata cannot be resolved. Deleted Komga entities, invalid paths and ambiguous matches are skipped rather than used as overwrite candidates.

## Validation

The release adds regression coverage for:

- Linux, Windows and UNC Komga file paths;
- `file:` URI variants and percent encoding;
- longest-prefix and filesystem-root path mapping;
- path boundary and case behavior;
- direct Komga API invariants;
- API-key and Basic-auth support;
- non-admin path-redaction detection;
- bounded/stable pagination;
- duplicate-path rejection;
- administrator-only Jellyfin Test/Sync actions; and
- protection against writing Komga content language into Jellyfin metadata-provider language.

## Updating

Existing Advanced Reader preferences, Jellyfin reading progress and One-Shot resolver settings remain compatible.

After installing v0.18.0.0, restart Jellyfin. Direct Komga metadata synchronization remains disabled until explicitly configured and enabled.
