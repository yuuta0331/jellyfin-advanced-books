## Highlights

- **v0.16.1 UI preserved:** the centered compact bottom pill, idle page/range pill, mobile floating chrome, and mobile **…** More menu remain the intended Reader design.
- **Cascade-order fix:** Preferences now re-applies its existing v0.16.1 presentation stylesheet after Reader Core creates its base stylesheet, preventing a mixed half-Core/half-v0.16.1 layout on PC or mobile.
- **One zoom state:** toolbar, keyboard, Ctrl+wheel, double-tap, preference restore, and pinch now update the same Reader-owned zoom/pan state.
- **Live focal pinch:** scale and two-finger midpoint translation are applied continuously through the real Reader transform.
- **Continuous-mode repair:** Vertical/Webtoon Fit Screen now changes image height with zoom and preserves the actual touched image point where possible.
- **Catalog artwork rollback:** the earlier Advanced Books artwork is restored for Jellyfin's plugin detail surface.

## Reader UI

The visual reference for this release is **v0.16.1.0**.

No intentional redesign is made to the Reader chrome. The release keeps:

- the centered compact desktop bottom navigation pill;
- the collapsed idle page/range pill plus thin progress rail;
- the floating rounded mobile top/bottom chrome;
- the mobile **…** menu containing Fullscreen and Help;
- direct Close, metadata, Pages, and Settings actions;
- the existing desktop Settings panel and mobile resizable Settings/Help bottom sheets.

The regression was caused by stylesheet ordering: `advancedbooks:reader-opening` runs before Core creates its stylesheet, so the v0.16.1 Preferences presentation sheet could be inserted first and then partially overwritten by Core rules with equal specificity. Preferences now moves that same stylesheet to the end after the Reader overlay exists. The v0.16.1 visual values themselves are unchanged.

## Zoom and pan

- Reader Core is the sole owner of `zoom`, `panX`, `panY`, fit sizing, touch-action, and `setZoom()`.
- `advancedBooksZoom.js` contains reusable focal geometry and is registered as a required runtime bridge; Core resolves it when zoom is used, without depending on JavaScript Injector's persisted entry order.
- Gestures no longer replaces `reader.setZoom` or `reader.applyTransform`.
- Pinch frames pass the previous midpoint as the source anchor and the current midpoint as the target anchor.
- Paged pan is clamped to actual rendered image/spread bounds during both zoom and subsequent drag.
- Paged pan is re-clamped after viewport resize or device rotation.
- Double-tap and Ctrl+wheel share the same focal coordinate path as pinch.

## Vertical Continuous and Webtoon

- Fit Screen scales its image-height cap with Reader zoom instead of remaining fixed to the original viewport height.
- Focal zoom anchors to the actual image under the pointer/fingers when available, with the page slot as a whitespace fallback.
- Fit Width, Fit Height, and Original Size use the same source-to-target focal restoration.
- Native one-finger scrolling remains available at normal zoom.
- Turning **Touch gestures** Off immediately restores native two-axis browser panning.

## Preserved v0.17 behavior

- two-way Jellyfin ComicsPlayer / Advanced Reader position interoperability;
- lifecycle-safe progress persistence on document hidden, pagehide, and beforeunload paths;
- played-state interoperability;
- direct Advanced Reader launch;
- optional native Jellyfin Book action replacement across detail, card, list, remote, and context-menu actions;
- explicit Replay/Start-over beginning at page 1.

## Validation

CI now verifies:

- the v0.16.1 compact pill, mobile floating chrome, and mobile More-menu rules remain present;
- the Preferences presentation stylesheet is reordered after Core creation;
- the old layered `installAnchoredZoom`, `reader.setZoom = ...`, `reader.applyTransform = ...`, and temporary pinch-preview paths do not return;
- Zoom Geometry is embedded and registered as a required runtime resource;
- Fit Screen height scaling, moving pinch midpoint tracking, paged pan clamping, and touch-action resynchronization remain present;
- every injected Reader script stays below the 96 KiB defensive limit and all built resources are present in the final DLL.

## Updating

Existing Reader preferences and Jellyfin reading progress remain compatible. Restart Jellyfin after installing the update.
