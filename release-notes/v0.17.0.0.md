## Highlights

- **Lifecycle-safe progress:** the latest Advanced Reader page is flushed when the tab/app becomes hidden and again on page exit, reducing lost progress when closing immediately after navigation.
- **Shared Jellyfin progress:** Advanced Reader and Jellyfin's built-in ComicsPlayer continue to use the same authoritative per-user page position in both directions.
- **Complete native action replacement:** supported Books can open Advanced Reader from details, Home/Library cards, lists, keyboard/remote commands and context menus.
- **Stable Reader launch:** the standalone Advanced Reader button and the direct `openItem` / `supportsItem` bridge include the v0.16.1 hotfix.
- **Reader UI and zoom fixes:** interaction-aware auto-hide, Settings/Help structure, page-position visibility, anchored zoom and pinch fixes are included.
- **Refreshed Catalog branding:** the dedicated purple/blue open-book Catalog icon remains aligned with the README visual language.

## Progress Reliability

- Keep the existing 1.2-second debounced progress save during normal reading.
- Capture the latest visible page when the document becomes hidden.
- Flush again on `pagehide` and retain `beforeunload` as the final fallback.
- Use Jellyfin Web's authenticated `ApiClient.fetch(..., true)` path with `keepalive: true` for lifecycle-exit progress PUTs.
- Preserve a pending lifecycle keepalive request when a normal progress write is already in flight.
- Keep the newest queued page as the authoritative pending client position.

## Jellyfin Progress Interoperability

- Store progress in Jellyfin's normal per-user `UserItemData.PlaybackPositionTicks`.
- Preserve the built-in ComicsPlayer mapping of zero-based page N to `N × 10,000` ticks.
- Progress written by the built-in ComicsPlayer is restored by Advanced Reader.
- Progress written by Advanced Reader is restored by the built-in ComicsPlayer.
- Generic Play/Resume asks the server for shared progress rather than relying on stale mounted DOM playback attributes.
- Explicit Replay / Start-over begins on page 1.
- Reaching the final page marks the Jellyfin Book played; intermediate reread progress does not clear an existing completed state.

## Jellyfin Web Integration

- Cover legacy detail Resume / Replay and modern detail Play / Resume.
- Cover Home/Library card actions, list actions, keyboard/remote commands and item context menus.
- Use host item-type information when available to avoid unnecessary non-Book probes.
- Fall back to Jellyfin's original behavior for unsupported, inaccessible and non-CBZ/ZIP items.
- Keep the optional native replacement setting off by default.

## Reader UI & Zoom

- Keep controls visible during active pointer, drag, scrubber, form, wheel and panel interaction.
- Keep Settings and Help headers fixed while their bodies scroll independently.
- Retain the functional mobile Settings resize/close handle and keyboard controls.
- Retain the per-user Page position Show/Hide setting without disabling the progress rail or internal resume tracking.
- Keep paged pinch on the real Reader transform with no preview-to-commit jump.
- Clamp Fit Screen pan against the rendered page/spread and keep Fit Screen/Width focal zoom anchored.
- Keep Vertical/Webtoon pinch anchored to the actual page slot under the gesture.

## Catalog & Validation

- Continue using `assets/advanced-books-plugin-icon.png` for Jellyfin Catalog metadata.
- Keep build metadata, manifest generation and release tests aligned to the same Catalog icon URL.
- Add regression guards requiring visibility/page-exit lifecycle hooks, authenticated keepalive progress writes and keepalive queue propagation.

- Existing Jellyfin reading progress is reused directly; no migration is required.
- Restart Jellyfin after updating the plugin.
